# The installable build (`make cia`)

`t2k.3dsx` is the development build: you launch it from the Homebrew Launcher
and it reads everything from `sdmc:/3ds/t2k/`, which you populate by hand.

`t2k.cia` is the same game **packaged as a title** — an icon on the HOME menu,
and the soundtrack and a first-boot config carried **inside it**. Install it and
it plays; there is nothing to copy to the card.

    make cia            # from the repo root
    # -> t2k_3ds/t2k.cia   (~310 MB, almost all of it audio)

Install with FBI (or any CIA installer). It is a normal title afterwards:
HOME-menu icon, its own save data, uninstallable from Data Management.

## What is in it

| Path in the title | Comes from | The game does |
|---|---|---|
| `romfs:/music/*.dsp,*.mod` | `data/music/` | **plays in place** — never copied to the SD |
| `romfs:/music/albums.json` | generated by `gen_albums.py` against that exact pool | the album map |
| `romfs:/t2k_config.json` | `cia/default_config.json` | **seeded** to `sdmc:/3ds/t2k/` on first boot only |

The split is deliberate. The music is read-only, so a second copy on the card
would waste ~300 MB for nothing. The config is *written* — settings, highscores
— so it has to live somewhere writable, and the bundle only supplies the
template the first time.

**`levels.json` and the album manifest are already embedded in the binary** and
need nothing here.

## The card always wins

Every lookup prefers `sdmc:/3ds/t2k/` and falls back to the bundle — the same
law `levels.json` and `albums.json` already follow. Drop a new album on the
card and it takes over; the bundle is the floor, not a ceiling.

One wrinkle worth knowing: the music check is *"does this directory contain
tracks"*, not *"does it exist"*. An empty `sdmc:/3ds/t2k/music/` — which a
half-finished copy easily leaves behind — would otherwise mask a perfectly
good bundle and you would hear only the two embedded MOD songs.

If the albums ever look wrong, the game writes `sdmc:/3ds/t2k/music.log` at
every boot saying which pool it read and what it found in it.

## Where the pieces come from

- `icon.png` (48×48), `icon_small.png` (24×24) — frames of the **game's own
  title screen and level 1**, captured from the PC build. The icon is the
  square tube with the wordmark across it; the wordmark alone filled only a
  third of the square.
- **the banner is a 3D MODEL, not a picture** — see below. It is level 15's
  tube, turning the way the level-select screen turns it. `banner.png`
  (256×128) is the old flat banner, kept only as a fallback.
- `banner.wav` — the "Super Zapper Recharge" cue, the same mastered sample
  (`.sfx_preview/SUPERZAP_FINAL.wav`, frozen in `sfx_data.cpp` per
  `assets/sfx/tempest2000/README.md`) already baked into the game's own SFX
  bank. **Not original** — like the rest of that bank, it is extracted
  Jaguar Tempest 2000 ROM audio (via `mwenge/tempest2k`), so this is no
  longer third-party-audio-free the way the earlier synthesised arpeggio
  was. Accepted because the CIA is already a personal, unpublished artifact
  (see "Do not publish the artifact" below) — the soundtrack alone already
  rules out distribution.
- `t2k.rsf` — the makerom spec. `UniqueId` (`0xF7A2C`) is the title's identity
  to the console: **changing it makes the next install a separate title**
  rather than an update, leaving the old one on the menu with its save data.
  Pick once, never move.

## The banner is level 15's tube, turning

`tools/build_banner.sh` builds `banner.cgfx` from one of two generators:

| `BANNER_GEN=` | what it makes |
|---|---|
| `gen_banner_level.py` (default) | **level 15's tube**, textured with that level's own procedural skin, turning the way the level-select screen turns it. `BANNER_LEVEL=` picks the level, as the level-select screen numbers it; `BANNER_SHADING=` picks where its colour band is spent. |
| `gen_banner_model.py` | the icon's composition, static: the square web dead on with the T2K wordmark across the bottom |

The level-tube banner reads everything from the game — the outline from
`levels.json` (rebuilt as `web_preview.cpp` does), the skin from the **real
DSL** (`tools/texdump.cpp` linked against `textures.cpp`), the shading law from
`lightenLevel`, the fog from `renderer_c3d.cpp`, the band from
`WEB_COLOR_BATCHES`, and the motion (`TUBE_LEN`, `CAM_PITCH`, `ROLL_RATE`,
`SKIN_BANDS`) from `ui/level_select.h`. One turn every 11.42 s, its own
`ROLL_RATE`; 424 KB against the 512 KB cap.

Three things worth knowing before editing it:

- **The spin is a Z roll wearing a Y yaw's clothes.** pycgfx cannot animate a
  turn about Y (that Euler term comes out of an `asin`). `Rx(-90)·Rz(t)·Rx(+90)`
  *is* `Ry(t)`, so the barrel is authored pre-turned and the parent carries
  `Rx(-90)` alongside `CAM_PITCH`.
- **Only part of the skin fogs.** The merged TEV stage is
  `fog(texA·vcw) + texB·wtb·vcw` — the additive plane never sees fog — so the
  bake applies fog at the share plane A actually contributes, measured from the
  two planes' means. Fogging all of it crushed the throat to a quarter
  brightness where the game keeps it near two thirds.
- **The framing is solved for the extent, not the reach.** `solve_framing`
  centres what the camera sees, scales to the range's half-extent, and pins the
  nearest point of the whole turn just behind the near plane. Bounding max|y|
  instead measured 0.96 and rendered 0.62 — the missing third was empty sky
  above a barrel that CAM_PITCH hangs below centre.
- **Stroke widths are judged at `--w 256`**, the banner's real width, not in a
  comfortable preview. 0.030 of the ring radius is visibly heavy, 0.020 solid,
  **0.013 the thinnest that stays continuous — what ships** — and 0.010 puts
  the rails under a pixel and dashes them.

Colour is authored rather than copied. The surface keeps `lightenLevel` for
**brightness only** and takes its hue from the level's band — because cycle
shading is per-tube in play (the whole web is one point in its band at any
instant) and a still model cannot wait for the sweep. `BANNER_SHADING` picks
which axis of the object the band is spent across:

- **`lane`** (default) — one hue per lane around the ring, constant within a
  lane, with the outline as the subject and the skin scaled by
  `SURFACE_UNDER`. The colours are the level's band and nothing else, so a
  band 1 level comes out red → orange and a band 4 one emerald → jade with no
  per-level authoring.
- **`depth`** — spent down the barrel instead, folded about the middle so both
  rims match, the fold in value rather than hue (`BAND_LO` 1.0, `BAND_DIP`
  0.60).

`SURFACE_UNDER` past 1.0 is an **exposure, not a scale**: the surface law
already runs 0.76 at a lane border down to 0.1 mid-panel, so the excess clips
the borders and spends its range lifting the dark interior. That is why
`Mesh.add` clamps — glTF `COLOR_0` is a normalised attribute and a component
above 1.0 is undefined once the converter quantises it.

## The icon-composition banner (`gen_banner_model.py`) holds still

The wide panel under a title on the HOME menu is not an image: it is a **CGFX
scene the menu renders, whose animations it loops**. That is why retail banners
move and homebrew ones do not — bannertool's `-i banner.png` path stamps a
fixed template CGFX (a flat quad, no animation section at all) and pastes your
PNG on as its texture.

T2K builds the real thing. `tools/build_banner.sh` runs:

    tools/gen_banner_model.py    the square web -- level 2, the same tube the
                                 icon shows -- seen DEAD ON, its lanes
                                 radiating into a black vanishing point, with
                                 the T2K wordmark extruded into a slab across
                                 the bottom: the icon's own composition,
                                 measured off cia/icon.png
    pycgfx                       glTF -> CGFX (skyfloogle/pycgfx, fetched into
                                 tools/.ciatools/ on first use)

and the Makefile hands the result to bannertool with `-ci` instead of `-i`.

**It does not rotate** (user, 2026-09-08). An earlier cut spun the tube on its
axis with the wordmark swaying beside it; that is gone, and so is every
rotation in the scene.

**The proportions are the icon's, in units of the rim.** In `cia/icon.png` the
rim spans 44 px from row 2 and the wordmark's ink spans 42 px by rows 33..44,
so the wordmark is `LOGO_OF_RIM` = 0.955 of the tube's width and its middle
sits `LOGO_BELOW_TOP` = 0.830 of the rim's height below the rim's top edge.
Shipped: 0.954 and 0.830. `check_layout()` in the generator asserts both to
±3% — one pixel of a 48 px source is 2.3% of the rim — along with the near
plane and the fact that both objects sit on x = 0.

**It is symmetric, and that took work.** The geometry always was (both objects
on x = 0; the rim mirrors to 0.000000), but a still, dead-centre composition
exposes things a spinning one hides. Mirroring the render and subtracting it
found three: the band's hue sweep ran *around* the ring, so the tube was purple
on one side and blue on the other; the lane spokes took their hue from the lane
rather than from the *border* they run down, which is a different mirror map;
and each wall quad's split diagonal was fixed, so mirror-paired panels
interpolated the weave differently under perspective. All three are fixed — see
`lane_hue_params` and `Mesh.quad`'s `flip` — plus the weave itself is folded at
the lane midline. 26.6% of pixels differed from their mirror before; 7.2% of
the tube's do now, and 0.01% with the weave's own detail removed. What is left
is float noise where the weave is steep, and the wordmark, which is not a
palindrome.

**So why is it still a model?** Because the HOME menu renders banners in
**stereo**. A tube that really recedes from a real rim, with the wordmark
floating in front of it, has depth on the top screen; a flat quad wearing a
picture of the icon has none, whichever picture it wears. Static is not flat.

**The animation section is empty, on purpose.** The menu expects a `COMMON`
skeletal animation and `build_production.sh` refuses a banner with no `CANM`,
so the scene still carries one — two keys, both identity. The banner holds
still because the *keys* say so, not because the section is missing; that keeps
the guard below meaningful for the case it was written for, an animation that
goes missing by accident.

**Nothing in the model is authored twice.** The web outline comes from
`t2k_core/data/levels.json`, the wordmark from `t2k_core/src/data/logo_data.h`
(itself generated from the game's own vector font) and the colours from
`WEB_COLOR_BATCHES` in `web_palette.h` — and the wordmark's pink from
`logo_geometry.h`'s own `#f2baff` core and `#a824e8` aura, so the letters on
the banner are the letters on the title screen. Re-cut the level list, redraw a
glyph or move band 0 and the banner follows.

**The camera is not ours to choose.** The HOME menu renders banners through a
fixed 30° camera at (0, 1, 44.786) looking down −Z with a near plane at 26.5 —
a 40 × 24 window at z = 0. Every layout constant in the generator is in those
units, and nothing may come closer to the camera than z = +18.3 or it clips.

**One local change to pycgfx**, applied by `tools/patch_pycgfx.py`: honour
glTF's `emissiveFactor`. Upstream drops it, so every surface is lit only by the
one directional light it emits and anything angled away renders black — which
is fatal for a model whose whole look is emissive neon on black.

### Looking at it

There is no way to see a HOME banner on this machine: Mandarine does not render
them, and a CIA only shows its banner once installed. `tools/banner_preview.py`
renders the generated glTF through that same fixed camera so the composition
and silhouette can be judged before shipping:

    python3 t2k_3ds/tools/banner_preview.py t2k_3ds/build/banner-model out.png
    python3 t2k_3ds/tools/banner_preview.py t2k_3ds/build/banner-model out.png --w 256

The second is the banner's own width, which is where thin strokes either
survive or do not. `--strip N` renders N frames across the loop, which is now
how you *prove* it holds still: every row identical. Its shading is a stand-in
for the PICA's fixed-function pipeline, so trust it for framing, not for exact
brightness. Evidence: `docs/validation/banner-icon-match-2026-09-08.png`
(and `banner-3d-model-loop-2026-09-06.png` for the spinning version it
replaced).

`build_production.sh` additionally refuses a build whose `banner.cgfx` is over
the 3DS's 512 KB banner cap or carries no `CANM` section — both of those fail
*silently*, and would not be visible until the title was already installed on
somebody's console.

**To go back to the static PNG**, change the one bannertool line in
`t2k_3ds/Makefile` from `-ci $(CIA_BANNERCGFX)` to `-i $(CIA_DIR)/banner.png`.

## Tools

**Neither `makerom` nor `bannertool` ships with devkitPro**, and bannertool's
original repo is gone from GitHub. `tools/get_cia_tools.sh` builds both into
`tools/.ciatools/` (gitignored) the first time you run `make cia`; it prefers
anything already on `PATH`, and `MAKEROM=` / `BANNERTOOL=` override it.

## Do not publish the artifact

The romfs is ~300 MB of **copyrighted game soundtracks** read from the
gitignored `data/music/` pool. Nothing it carries is in this repository, and
the `.cia` you build is a personal artifact — the same rule `.gitignore`'s
`soundtracks/` block already states. A pool-less machine still builds a valid
CIA; it just ships without the CD soundtrack, and says so.
